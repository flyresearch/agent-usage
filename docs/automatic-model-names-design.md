# 自动识别模型名称设计（提案）

状态：采集器已实现（p2b-12），默认关闭；UI 配置编辑器已适配并验证配置往返。实机部署状态须以当前 fleet 报告为准。

## 问题与目标

当前每个来源的模型名必须命中私有配置 `model_aliases`，否则用量仍被计入，但模型显示为 `unknown`。新增模型需要逐机维护映射、更新 fleet 配置指纹并重新采集。最近的 `gpt-6.1-terra` 和 `claude-opus-4-6` 就属于名称在源记录中明确存在，但没有配置映射的情况。

目标是在不依赖 provider 网络请求、不丢失用量、不猜测调用归属的前提下，自动显示符合本机既定信任策略的新模型名；同时保留手工别名、未识别与价格未知等状态。此方案不承诺自动认识任意自定义模型，也不声称能证明模型名是真实的公开型号。

## 核心限制：可读名称与隐私

模型字段是外部输入，可能是代理商、自托管服务或用户自定义的字符串。合法字符、长度、`gpt-` 等前缀，甚至看起来合理的型号，都不能证明名称不含私人信息，也不能证明调用由相应厂商提供。公开模型目录的精确名称可以核对，但固定目录无法自动覆盖未来任意名称。

因此提供两个明确的本地策略，默认沿用现有行为：

- **`explicit`（默认）**：仅导出显式配置的别名。保持当前隐私和兼容语义。
- **`pattern`（自愿启用）**：别名未命中时，仅对本地配置明确授权的来源和完整模型名规则进行匹配；命中后输出原始模型名。操作者接受满足规则的自定义名称也可能被导出到本机快照和 fleet 汇总这一风险。

不使用内置厂商前缀作为隐私保证，不从模型名推断 provider、backend、价格或调用归属。模型名称不安全或无法判断时继续 `unknown`；不自动把其哈希视为匿名化，低熵名称容易被反查。

## 配置与解析规则

在现有配置上新增可选字段 `model_name_policy`，缺省为 `explicit`。`pattern` 使用下列固定语法；不接受正则、通配符或其他字段：

```json
{
  "model_name_policy": {
    "mode": "pattern",
    "sources": {
      "example-codex": ["gpt-"],
      "example-claude": ["claude-opus-", "claude-sonnet-", "claude-haiku-"]
    }
  }
}
```

规则为**字面前缀 + 数字开头的非空后缀**：先逐字节、区分大小写匹配整个字面前缀；剩余部分首字节必须是 ASCII 数字，其余字节只能是 ASCII 字母、数字或 `._-`。整个名称必须通过协议 `label` 校验（1–64 字节），并完整消费；不截断、不转换、不忽略空白。例如 `gpt-6.1-terra` 命中 `gpt-`，`gpt-private` 不命中，但 `gpt-6-private` 会命中，后者展示了此规则的隐私风险。这是前缀授权，并非厂商命名规范或隐私检测。

每个前缀为 1–48 字节，必须以 ASCII 字母开头，全部由 ASCII 字母数字及 `._-` 组成，最后一个字节必须是 `-`；每个来源 1–32 个不重复前缀，最多 64 个来源。来源键必须唯一且对应配置中的实际 source ID。空表、重复规则、非法前缀、未配置来源、未知模式、未知字段或类型错误均以固定 `invalid_config` 失败；JSON 重复对象键必须在解析时拒绝，不能静默覆盖。只允许缺省字段表示 `explicit`；存在字段时必须是完整的 `pattern` 对象，避免同义配置造成不同指纹。匹配器对每个规则做有界字节比较，复杂度至多与规则数乘以名称长度成正比；配置及名称上限在匹配前检查。配置验证、解析与缓存复核共用同一实现。示例规则仅用于解释语法，并非推荐直接授权所有来源。

按以下顺序解析每个已可靠关联到用量记录的原始模型名：

1. 命中 `model_aliases` 时使用显式映射；显式配置始终优先。
2. 否则只有 `pattern` 模式下，来源 ID 有授权规则、原始值通过完整匹配且通过现有协议 `label` 校验（1–64 字节 ASCII 字母数字及 `._-`）时，才原样输出。
3. 其他情况输出 `unknown` 并维持 `unknown_model_records` 计数；缺失与未获授权都不能当作真实零用量。`unknown` 为保留值，不允许自动识别把它当成已识别模型。

显式别名仍是处理 `/`、`:`、私人名称和同义型号的方式。不同原始名称即使相似也不自动合并；不同 provider 使用相同原始名称时可能在模型视图合并，provider/backend 等已有维度仍按自身证据保留。若用户需要不同显示名称，应使用显式别名；不自动补 provider 前缀。

策略只解决**已有可信模型关联之后的命名**。Codex turn/response 和 compaction 身份核对、Claude 流式合并、OpenClaw 后端归属等现有规则保持原样；没有模型字段、关联不匹配或证据不足时不能从其他记录或当前设置推断。Hermes 无法按模型归属的 residual 仍是 `unknown`。

## 数据契约、缓存与多机

- 快照 v1 的模型仍是现有字符串字段，不需要为了显示名称新增协议字段；`unknown_model_records` 的含义仍为无法输出受控模型名的记录数。自动匹配只是命名授权，不代表历史覆盖或价格覆盖完整。
- **旧配置指纹保持不变**：新增字段表示为可缺省字段；缺省时序列化必须完全省略，且原有字段顺序与表示不变，使旧版和新版对同一旧配置产生逐字节相同的配置序列化结果和 SHA-256。显式 `null`、空对象和 `explicit` 对象均拒绝，不能被悄悄归一化为缺省。`config-id` 与 `collect` 共用配置解析、验证和指纹函数。启用或调整规则后指纹变化；之后新名称命中既有规则无需再改配置或指纹。必须使用固定旧配置字节与旧版期望指纹的 fixture，并验证缺省字段序列化字节，不仅比较两个新版结果。
- 更改 parser 版本并使旧解析缓存失效；冷解析和暖缓存结果必须一致。路径遍历得到 `(source_index, path)` 后，以当前已验证配置中的 `source_index` 取得 source ID；不要采用缓存内自报的来源。每次取得新解析或缓存命中的 `Parsed` 后、合并和生成任何投影之前，对每条记录检查：`unknown` 允许；显式别名值按现有全局别名语义允许；其他值必须通过当前来源的规则和 `label`，且 `model_key` 等于该值原始字节的 SHA-256。失败返回固定 `invalid_cache_projection`，整机本轮不发布。解析器仍先按原始名称查显式别名，不能以输出值反向推断其原始名称。现有最后快照校验同步调整为基于行的 `source_id` 执行相同授权检查，作为纵深防御，不得只校验全局规则并集。
- 缓存命中仍由当前遍历出的路径哈希及文件 stamp 决定；当前配置已拒绝重叠路径和重复物理文件。测试把来源 A 的缓存记录注入来源 B 的命中条目，使用只授权 A 的名称验证 B 失败。来源、路径或策略变化会改变配置指纹并失效旧缓存；数据库依旧在只读事务中读取已提交 WAL，不依赖文件 stamp 命中。缓存是私有可信状态，名称和哈希检查是防止越权投影的校验，不是对恶意篡改的认证；不得声称 SHA-256 可认证缓存或证明来源。
- 出现配置变更、采集失败、旧版本或新版本混用时，沿用 fleet 配置指纹、整机 last-good 和 freshness 规则；升级顺序及回滚需要单独验证。旧 collector 无法解析新增配置字段时不可先在其上启用新配置。旧快照可读，但不会自动重新归类；需要成功重采集。
- 新模型没有对应离线价格时保持未定价，并在 UI 沿用价格覆盖提示；不得为名字相似的模型继承价格。相应 UI 价格匹配与模型合并行为须在实施时独立核验，不能因本文假定已支持。
- 不记录或导出未授权原始名称、正文、工具参数、路径或凭据；诊断使用固定错误码和计数。名称被授权后会进入快照、缓存和 fleet，是策略明确接受的数据流。

## 验收与实施顺序

规则语法和兼容性约束如上；实际各来源授权范围仍由操作者选择。本文不授权自动修改实机配置、部署或发布。

1. 各 JSONL 和 SQLite adapter 共用一致的命名决策，覆盖 Codex compaction 的重新归属路径；不改变原有去重、token bucket 或来源关联规则。
2. 人工 fixture 调用实际 parser/collector：明确别名优先、合法新名称命中、来源隔离、完整匹配、近似前缀和非法/超长/空值拒绝、保留 `unknown`、配置无效失败，以及自定义敏感样例不符合规则时不出现在快照或诊断。匹配规则内的私人名称必须作为风险示例，验证它确实会被导出，不能误称规则能检测隐私。
3. 验证真实关联边界：不匹配的 Codex turn/compaction、缺模型的记录和 Hermes residual 仍为 unknown；使用量、调用数、去重、coverage 与日桶守恒保持正确。
4. 验证旧配置与旧快照兼容、规则变更导致缓存失效、冷暖结果一致、缓存中不符合所属来源授权的模型拒绝发布；测试多机配置版本切换、旧 collector、last-good、回滚与失败不覆盖。
5. 用合成数据验证新型号显示、没有价格时不定价，以及旧 UI 消费新快照；再按明确授权开展实机升级和多机采集验证。记录 source、fixture 和实机结果，不将任一层的成功等同于全部完成。

## 评审决策

推荐默认 `explicit`、按来源自愿启用 `pattern`，因为自动输出未知未来名称与保证不泄露任意私人字符串无法同时满足。待确认的是各来源愿意授权的具体前缀，以及是否需要 UI 提示模式带来的数据流；在这些决定和实际价格匹配行为核实之前，不应宣称所有新模型都能安全自动识别或自动计价。

## 实施记录与已知限制

采集器在 p2b-12 实现可选策略和来源绑定的缓存校验；旧配置不变更指纹。独立 UI 的 `PriceCatalog.estimate` 使用模型名称精确查表，未命中且 token 非零时返回未定价。新版 UI `ConfigurationEditor` 可保留 `model_name_policy`，来源删除或改名时拒绝静默丢弃规则；旧版编辑器会拒绝该字段。实际部署与 UI 交互状态需分别验证；源码和合成测试不证明实机使用状态。
